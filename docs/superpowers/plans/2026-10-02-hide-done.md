# Store "hide done" per user on the server — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

## Context

The "Hide done" state lives in the URL (`?hide_done=1`) and in a hidden input `#hide-done`
that every item request must include (`hx-include`). It is lost on `/` without the query
(bookmark, login, other device), and a missing `hx-include` gives a wrong response. The user
chose to store it per user on the server.

Worktree `~/claude-personal/todo-worktrees/hide-done`, branch `hide-done`, from `main`
(`2097446`). Native execution, one commit per task, then a fresh whole-branch review. No
push. No visible UI change (same button, same texts), so no Claude Design page.

## Design

1. **Schema v3:** `ALTER TABLE users ADD COLUMN hide_done INTEGER NOT NULL DEFAULT 0`,
   `PRAGMA user_version = 3`. `migrate`: version < 2 → today's path (creates v2), then the v3
   step; version 2 → only the v3 step (keeps all data); version ≥ 3 → nothing. One constant
   `currentVersion = 3`, also used by the admin check (`RequireCurrent`).
2. **auth:** `User.HideDone bool`, read by `SessionUser` (no extra query per request).
   `Store.SetHideDone(ctx, userID int64, hide bool) error` (ErrNoUser);
   `Service.SetHideDone(ctx, userID, hide)`.
3. **web:**
   - new route `POST /settings/hide-done` (protected), form `hide_done=1|0`: saves, then
     renders the list section like the htmx `GET /` (without htmx: 303 to `/`).
   - every handler reads the state from `currentUser(r).HideDone` (or the value just saved);
     `hideDoneFrom` and the hidden input `#hide-done` are removed, and so are all
     `hx-include="#hide-done"` (`list.html`, `form.html`, `item.html`); the edit row keeps
     `hx-include="closest li"`.
   - toolbar button: `hx-post="/settings/hide-done"` with
     `hx-vals='{"hide_done":"1"}'` or `'{"hide_done":"0"}'`; no `hx-push-url`.
   - `GET /?hide_done=1` from old bookmarks is ignored (the saved state applies).
4. **Docs:** todo-app spec (routes table and the "hide state is in the URL" paragraph), users
   spec (schema), plan copy.

## Review Focus

1. A database at version 2 with users, sessions and items migrates to 3 without losing data;
   the admin commands accept 3 and reject 2 with "start the server once". → Task 1 tests.
2. The state is per user: user A hiding done items does not change user B. → Task 2 test.
3. Toggling an item to done while done items are hidden removes the row, with no form value
   sent. → Task 2 test (the old form-value tests are rewritten).
4. A second session of the same user (another device) sees the saved state. → Task 2 test.
5. No page or fragment still renders `#hide-done`, `hide_done=1` links, or `hx-include="#hide-done"`. → Task 2 test (`assertNotContains`).
